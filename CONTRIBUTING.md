# Contributing

## Code standard

- Prefer clear names over short names.
- Use `nullptr` instead of `NULL` in modern C++.
- Include only the headers required by the example when practical.
- State time and space complexity.
- Keep examples focused on one concept.
- Add edge cases to problem solutions.
- Do not commit generated binaries such as `.exe`, `.o`, or `.obj`.

## Problem solution standard

Each substantial problem should document:

1. Problem
2. Observation
3. Brute force
4. Optimized approach
5. Correctness intuition
6. Complexity
7. Edge cases
8. C++ implementation
9. Related patterns/problems
