## Every major topic should answer five questions

1. **What is it?**
2. **Why does it work?**
3. **How do I implement it in C++?**
4. **When should I recognize it in a problem?**
5. **What mistakes and edge cases should I watch for?**

## Recommended learning order

`00` → `01` → `02` → ... → `22` → `Patterns` → `Problems`

Do not skip prerequisites just because an advanced algorithm looks interesting.

## Repository design

The repository has three complementary views:

**Topic view:** learn a data structure or algorithm.

**Pattern view:** learn how to recognize recurring problem structures.

**Problem view:** practice applying the ideas.

## Code policy

Examples are intended to be readable and independently compilable where practical. Canonical implementations use modern C++ conventions such as `nullptr`, explicit ownership cleanup for raw-pointer teaching examples, and clear complexity notes.
